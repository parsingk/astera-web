Astera/기능

MCP는 한 번 설정해 모든 계정에서 쓰세요.

Astera는 MCP 서버, 스킬, 플러그인을 자신이 시작하는 모든 세션에 나눠 주고 에이전트는 Astera의 MCP 서버로 Job을 다룰 수 있습니다.

양방향으로 쓰는 MCP

Astera는 MCP를 두 방향으로 다룹니다. 설정해 둔 MCP 서버, 스킬, 플러그인을 모든 계정에서 Astera가 시작하는 Claude Code와 Codex 세션에 나눠 줍니다. 그리고 Astera 자체가 MCP 서버여서 Claude Code, Codex, Cursor 클라이언트가 Job을 만들고 실행 회차를 따라가며 검사 결과를 읽을 수 있습니다.

MCP 서버를 모든 계정에 공유

설정 → MCP & Skills에서 등록을 누르고 계정을 고른 뒤 공유할 MCP 서버, 스킬, 명령, 에이전트를 선택하세요. 모든 계정의 새 세션에 적용되고 사용량 한도에 걸려 다른 계정으로 옮겨 간 세션에도 적용됩니다. 제공자별 지원 범위는 그대로여서 Codex에는 슬래시 명령과 하위 에이전트가 없습니다.

프로젝트마다 하나, 또는 세션마다 하나

공유한 로컬 MCP 서버는 Host의 Gateway를 거쳐 프로젝트 폴더마다 하나씩 실행됩니다. 5분 동안 쓰지 않으면 멈추고 비정상 종료 뒤 다시 필요해지면 시작합니다. 세션마다 상태를 따로 둬야 하면 세션마다 실행을 켜세요. Playwright, chrome-devtools 같은 브라우저 서버는 기본으로 세션마다 실행되며 세션별 브라우저 프로필을 씁니다.

비밀 값은 보이지 않게

MCP 환경 변수 값은 본인만 읽을 수 있는 저장소로 옮겨집니다. 설정과 CLI에는 이름만 나오고 값은 나오지 않습니다. Gateway는 세션마다 토큰을 따로 발급합니다. 바뀐 도구는 새 세션부터 적용됩니다.

사본은 항상 같게

Astera는 계정마다 있는 파일 사본을 같은 상태로 유지합니다. 관리 중인 사본을 지우면 복원하고 수정한 사본은 백업한 뒤 복원합니다. 계정에 원래 있던 다른 버전은 공유 버전으로 바꾸기를 고를 때까지 그대로 둡니다.

Claude Code 플러그인도 함께

같은 탭의 플러그인 묶음에서 Claude Code 플러그인을 공유합니다. Astera는 플러그인마다 사본 하나를 설치해 자신이 시작하는 모든 Claude 세션에 불러오므로 모든 계정이 같은 버전을 씁니다. 새 버전이 나와도 행에 표시만 하고 업데이트를 누르기 전에는 아무것도 바꾸지 않습니다. 가이드: MCP & Skills

astera ext list
astera ext sync

ext list는 공유 항목을 보여 주고 ext sync는 파일 사본을 맞춥니다. 둘 다 앱과 Host가 꺼져 있어도 동작합니다.

에이전트가 Astera를 다루게 하기

Astera의 MCP 서버에 연결한 클라이언트는 앱이나 CLI와 같은 로컬 Host를 씁니다. MCP로 만든 Job은 Astera와 CLI에도 나타나고 클라이언트 연결이 끊겨도 계속 실행됩니다. create_job은 Job을 저장하고 run_job은 실행을 시작합니다. wait_for_run은 진행을 따라가고 get_completion은 작업의 검사 결과를 읽습니다.

클라이언트 연결

astera 명령을 설정 → CLI에서 설치하세요. 같은 화면에 운영체제와 클라이언트별 설정 명령이 나오고 Claude Code와 Codex에는 등록 버튼도 있습니다. 직접 추가하려면 이렇게 합니다.

claude mcp add astera -- astera mcp serve
codex mcp add astera -- astera mcp serve

프로젝트의 .mcp.json에 쓸 수도 있습니다.

{
  "mcpServers": {
    "astera": { "command": "astera", "args": ["mcp", "serve"] }
  }
}

Windows의 Claude Code는 claude mcp add astera -- cmd /c astera mcp serve를 써야 합니다. 등록은 각 클라이언트의 기본 사용자 설정에 들어가므로 설정 폴더를 따로 쓰는 Astera 계정에는 항목을 따로 추가해야 할 수 있습니다. 준비 상태는 astera mcp status로 확인하세요. MCP 문서(영어)

클라이언트에게 허용할 범위

  • MCP 접근: 읽기 전용은 조회만, 기본값인 읽기와 제어는 Job 생성과 실행까지 허용합니다. 꺼짐은 모든 도구 호출을 거부합니다. 접근 권한은 호출할 때마다 확인합니다.
  • MCP 클라이언트가 세션을 보고 사용하게 하기는 기본으로 꺼져 있으며 켜면 본인 세션을 포함한 Astera 세션이 노출됩니다. 클라이언트가 시작한 세션에는 기본으로 켜져 있는 권한 확인 없이 에이전트 실행이 적용됩니다.
  • MCP 클라이언트가 GitHub 에서 작업하게 하기는 기본으로 꺼져 있으며 켜면 PR 생성, CI 재실행, 신뢰할 수 있는 이슈로 Job 만들기를 허용합니다. PR, CI 검사, 이슈를 읽으려면 Host 컴퓨터에 gh가 로그인돼 있어야 합니다.

기본은 로컬 연결

astera mcp serve는 표준 입출력으로 통신하고 네트워크 포트를 열지 않습니다. Host가 꺼져 있으면 로컬 클라이언트가 연결할 때 Host를 시작합니다. 설정 → CLI의 HTTP 로 MCP 제공은 기본으로 꺼져 있습니다. 일반 HTTP이고 Bearer 토큰 하나로만 확인하므로 신뢰할 수 있는 사설망에서만 쓰세요. Tailscale처럼 암호화된 연결이면 더 좋습니다. 포트를 인터넷에 공개하면 안 됩니다. 다른 컴퓨터를 다루려면 암호화된 연결인 Remote Runtime을 쓰세요.

요구 사항과 한계

  • 공유한 서버, 스킬, 플러그인은 Astera가 시작한 세션에 적용됩니다. Astera 밖에서 시작한 claude에는 공유 플러그인이 들어가지 않습니다.
  • 바뀐 도구는 세션이 시작될 때만 반영됩니다.
  • 설정 값이 필요한 플러그인, 비밀번호나 키가 들어 있는 마켓플레이스 주소에서 온 플러그인, 마켓플레이스에서 설치하지 않은 플러그인은 공유할 수 없습니다. Astera가 이유를 알려 줍니다.
  • 클라이언트는 설치한 astera 명령을 거쳐 Host에 연결합니다. 앱 창은 열려 있지 않아도 됩니다.

자주 묻는 질문

MCP 서버 공유와 클라이언트를 Astera에 연결하는 것은 같은 기능인가요?

아닙니다. 공유는 세션들에 같은 도구를 주는 기능이고 Astera MCP 서버에 클라이언트를 연결하면 그 클라이언트가 Job을 관리할 수 있습니다. 둘 중 하나만 써도 됩니다.

Astera 창이 열려 있어야 하나요?

아닙니다. MCP 클라이언트는 설치한 astera 명령으로 Host에 연결하고 Host가 꺼져 있으면 로컬 클라이언트가 시작합니다.

다른 컴퓨터의 클라이언트에서도 쓸 수 있나요?

Remote Runtime으로 두 컴퓨터를 페어링하세요. 그러면 클라이언트가 자기 컴퓨터의 Astera MCP 서버를 쓰면서 지원되는 도구에 runtimeId를 넘깁니다. HTTP로 MCP 제공도 다른 기기의 연결을 받지만 신뢰할 수 있는 네트워크의 일반 HTTP로만 쓰세요.

내 프로젝트에서 Astera를 써 보세요.

Astera는 Apache-2.0 라이선스의 무료 오픈소스입니다. 지금 쓰는 Claude Code와 Codex CLI를 그대로 실행하므로 모델 사용량은 본인의 Anthropic 또는 OpenAI 요금제에서 차감됩니다.
