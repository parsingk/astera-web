Astera/Features

Continue the work, not the whole transcript.

When a usage limit moves a session to another account, Smart Resume starts the next one fresh with a checkpoint of what was asked, what changed, and where it stopped.

Two ways to pick the work back up

When a usage limit moves a session to another account, the next session has to know what was going on. Replaying a long conversation carries everything, including the parts that no longer matter. Smart Resume starts the next session fresh and gives it a compact checkpoint instead.

Standard resume is the default. Choose between them in Settings → Agents → Session resume strategy.
Standard resumeSmart Resume
The next session getsThe existing conversation, continued through the CLI’s own resumeA new conversation whose first message is a checkpoint of the work so far
Good forShort conversations where every detail still mattersLong sessions where a focused handoff is more useful than the full history
Trade-offCarries the whole conversation into the next sessionA compact handoff can leave out older details

What the checkpoint carries

  • The working folder and its git state.
  • The conversation’s recent requests, in order, and the tail of the exchange.
  • The files the session touched and the last command it ran.
  • For Job workers, the task’s objective, dependencies, recent reports, decisions, and validation context, so the next worker sees both its task and the work around it.

Secrets are redacted on the way in. The next agent can then open the working files itself to pick up the task.

When it runs

Smart Resume is off by default. When it is on, it is used when a usage limit switches a session to another available account of the same service, in the rolling order you set for that session. If a checkpoint cannot be built, Astera falls back to the standard resume, so turning it on never leaves a switch worse off than before.

  1. Turn it on

    In Settings → Agents → Session resume strategy, choose Smart Resume.

  2. Set the rolling order

    In New session, choose the first account, then use + Add account for the next ones. Add only accounts you are entitled to use.

  3. Keep working

    When a limit triggers a switch, the next session receives the checkpoint as its first message. Smart Resume in the guide

What it does not do

  • It does not remove or raise any account’s usage limit. Every account keeps its own limits.
  • It is a handoff, not a copy of the conversation. Keep requirements the agent must not lose in project files it can read, such as CLAUDE.md or AGENTS.md.
  • It does not apply when there is no other account to switch to. A session on a single account can instead wait for the limit to reset and resume. Working with usage limits

Questions

Is this the same as claude --resume?

No. claude --continue and claude --resume reopen an earlier conversation, and Codex has codex resume for the same purpose. Astera’s standard resume uses the CLI’s own resume. Smart Resume starts a new conversation and hands it a checkpoint instead. Claude Code: resume previous conversations

Are secrets copied into the checkpoint?

Secrets are redacted while the checkpoint is built. The checkpoint still describes your files and commands, so treat it like the rest of your project history.
