에이전트는 한 컴퓨터에서, 관리는 다른 컴퓨터에서

Remote Runtime은 일을 두 컴퓨터로 나눕니다. Runtime은 Claude Code, Codex, 워크트리, 검사, 수정을 실행합니다. 컨트롤러는 사용자가 앞에 앉아 있는 컴퓨터로, 그 컴퓨터의 Astera 앱이나 astera 명령이나 MCP 클라이언트로 작업을 지휘합니다. Job은 컨트롤러에 매여 있지 않습니다. 컨트롤러가 잠들거나 꺼지거나 네트워크가 끊겨도 Runtime은 계속 일하고 컨트롤러는 다시 연결될 때 진행 상황을 받아 옵니다.

이럴 때 쓸모 있습니다

오래 걸리는 Job은 켜 두는 컴퓨터에 맡기기

노트북에서 Job을 시작하고 덮개를 닫은 뒤 나중에 확인하세요. 연결이 끊긴 컨트롤러는 Runtime의 마지막 상태를 보여 주되 최신 정보가 아니라고 표시합니다. 연결이 끊겼다고 Job이 실패한 것은 아닙니다.

워크스테이션에 있는 계정과 프로젝트 그대로 쓰기

작업은 Runtime의 계정과 경로로 실행됩니다. 새 원격 Job에는 그 컴퓨터의 폴더를 지정하고 세션은 그 컴퓨터에 등록된 프로젝트에서 시작합니다. Astera는 컴퓨터끼리 비밀 값, 로그인, 자격 증명을 복사하지 않습니다.

같은 세션을 두 곳에서 열기

컨트롤러에서 터미널이나 채팅 탭을 닫아도 Runtime의 세션은 계속 실행됩니다. 두 컴퓨터에 같은 터미널이 열려 있으면 마지막으로 입력한 쪽의 창 크기를 따르고 다른 쪽은 전체가 보이도록 축소합니다.

스크립트나 에이전트로 다루기

astera 명령 앞에 --runtime RUNTIME_ID를 넣거나 MCP 클라이언트에서 도구에 runtimeId를 넘기세요. Runtime에 연결할 수 없으면 컨트롤러에서 대신 실행하지 않고 오류를 돌려줍니다. 헤드리스 CLI

사설망에서 쓰도록 만들었습니다

  • Runtime은 TLS 키를 직접 만듭니다. 컨트롤러는 페어링할 때 그 지문을 고정하고 이후 다른 키는 거부합니다.
  • 페어링 문자열에는 이름이 붙고 한 번만 쓸 수 있으며 10분 뒤 만료됩니다. 컨트롤러마다 토큰이 따로 발급되고 토큰을 회수하면 그 컨트롤러의 연결이 바로 끊깁니다.
  • 읽기 전용은 조회만 허용합니다. 전체 제어는 Job과 세션을 시작하고 관리하는 것까지 허용하며 그 세션은 Runtime 사용자가 할 수 있는 모든 명령을 실행할 수 있습니다. 전체 제어는 그 사용자 계정을 맡겨도 될 컨트롤러에만 주세요.
  • 컨트롤러는 Job, 실행 회차, 작업, 세션을 ID로만 다룹니다. Runtime의 임의 파일을 읽거나 폴더 목록을 보거나 셸을 여는 명령은 없습니다.
  • 컨트롤러의 페어링을 해제하면 그 컨트롤러가 만든 예약 Job이 일시 정지됩니다. Runtime 앞에 있는 사용자만 다시 시작할 수 있습니다.

LAN, VPN, Tailscale을 쓰고 Runtime의 포트를 인터넷에 열지 마세요. Astera는 중계 서비스를 제공하지 않으며 포트를 대신 열지도 않습니다. Remote Runtime은 HTTP로 MCP 제공 기능과 별개입니다. 그쪽은 일반 HTTP라서 다른 컴퓨터에 안전하게 연결하는 방법이 아닙니다.

설정하기

  1. Runtime 준비

    두 컴퓨터에 Astera를 설치하세요. Runtime에는 Claude Code나 Codex를 설치해 로그인하고 프로젝트 폴더를 등록합니다. 두 컴퓨터는 LAN, VPN, Tailscale로 연결하세요.

  2. 원격 기능 켜기

    Runtime에서 설정 → 원격 Runtime → 이 컴퓨터를 열고 LAN 또는 Tailscale 주소를 고른 뒤 켜기를 누르세요. “이 컴퓨터만” 주소로는 다른 컴퓨터가 연결할 수 없습니다.

  3. 페어링 문자열 만들기

    이름을 붙이고 읽기 전용과 전체 제어 중에서 고르세요. 문자열에는 비밀 코드가 들어 있고 한 번만 쓸 수 있으며 10분 뒤 만료되므로 컨트롤러로 바로 옮기세요.

  4. 페어링하고 작업 시작

    컨트롤러의 설정 → 원격 Runtime에 문자열을 붙여 넣고 페어링을 누르세요. Jobs에서 Runtime과 프로젝트를 고르고 새 세션에서는 세션을 실행할 컴퓨터를 고릅니다.

컨트롤러의 터미널에서 페어링할 수도 있습니다.

astera runtimes add --pair -
astera runtimes list
astera --runtime RUNTIME_ID jobs list --human
astera --runtime RUNTIME_ID runs follow --id RUN_ID --human

첫 명령 뒤에 페어링 문자열을 붙여 넣고 Ctrl+D, Windows에서는 Ctrl+Z 다음 Enter로 입력을 마치세요. RUNTIME_ID는 목록의 ID나 이름으로, RUN_ID는 그 Runtime의 실행 회차 ID로 바꾸세요. 가이드: Remote Runtime

요구 사항, 한계, 비용

  • Runtime에는 Windows, macOS, Linux(데스크톱 세션의 .deb)용 Astera 데스크톱 앱이 있어야 합니다. 설정에 데스크톱 세션이 필요해서 데스크톱이 없는 Linux 서버는 아직 지원하지 않습니다. 컨트롤러는 셋 중 어느 운영체제든 됩니다.
  • Runtime은 깨어 있어야 합니다. 원격 기능이 켜져 있으면 예약된 Job이나 답을 기다리는 질문만 있어도 Host가 유지됩니다. Host가 꺼져 있는 동안 지나간 예약 시각은 건너뜁니다. 비정상 종료나 재부팅 뒤 Host를 다시 띄우는 운영체제별 방법은 Remote Runtime 문서에 있습니다.
  • 두 컴퓨터를 함께 업데이트하세요. 구버전 Runtime은 설정 보고서를 보내지 못하고 구버전 astera 명령은 에이전트로 취급됩니다.
  • 컨트롤러에 남는 일도 있습니다. How It Works 기록, GitHub 쓰기, 에이전트 브라우저와 앱 제어가 그렇습니다.
  • Astera 서버 요금이나 중계 서비스 구독은 없습니다. 직접 고른 것만 비용이 듭니다. Runtime 컴퓨터(VPS나 클라우드 컴퓨터를 쓴다면 그 비용), VPN 서비스, Runtime 계정의 에이전트 요금제나 API 사용량입니다.

자주 묻는 질문

노트북 연결이 끊기면 작업이 멈추나요?

아닙니다. 컨트롤러의 네트워크가 끊기거나, 잠들거나, 꺼지거나, 앱이 닫혀도 Job은 그대로 진행됩니다. Runtime이 계속 일하고 다시 연결하면 현재 진행 상황을 볼 수 있습니다.

클라우드 컴퓨터를 Runtime으로 써도 되나요?

네. Astera 데스크톱 앱이 돌아가면 됩니다. Windows, macOS, 또는 설정용 데스크톱 세션이 있는 Linux여야 합니다. 포트를 열지 말고 VPN이나 Tailscale로 연결하세요.

Astera가 내 로그인 정보를 Runtime으로 복사하나요?

아닙니다. 각 컴퓨터에는 거기서 로그인한 계정과 자격 증명이 따로 있습니다. Astera는 어느 방향으로도 컴퓨터끼리 비밀 값, 로그인, 자격 증명을 복사하지 않습니다.
