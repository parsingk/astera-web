창 없이 돌아가는 에이전트

astera 명령으로 어느 셸에서든 Claude Code와 Codex 세션을 시작하고 Job을 만들어 실행하며 검사 결과를 따라가고 질문에 답할 수 있습니다. Astera Host가 실행 중이면 앱을 닫아도 워커, 워크트리, 설정한 검사와 리뷰, 계정 자동 전환이 계속됩니다. 나중에 Astera를 다시 열면 같은 작업을 탭과 Jobs 화면에서 볼 수 있습니다.

셸에서 할 수 있는 일

앱을 열지 않고 에이전트 세션 시작

계정, 작업 폴더, 요청을 고르세요. 세션에 추가 요청을 보내기 전에는 먼저 화면을 읽으세요. 터미널 입력은 지금 화면에 떠 있는 곳으로 가기 때문에 권한 요청에 입력될 수도 있습니다. 사용량 한도에 걸렸을 때 같은 제공자의 다른 계정으로 이어 가려면 --roll-accounts에 그 계정들을 지정하세요.

astera sessions create --account ACCOUNT_ID --cwd "REPO_PATH" --kind terminal --prompt "Inspect the project and summarize its test setup."
astera sessions read --id SESSION_ID --human
astera sessions send --id SESSION_ID --text "Run the existing tests and report the results."

권한 요청은 직접 결정

채팅 세션에서 기본값인 --unattended hold는 권한 요청을 사용자가 답할 때까지 열어 둡니다. deny-after-60s는 1분 동안 아무도 답하지 않은 요청을 거절합니다. 답은 직접 연 셸에서 astera chats answer에 --allow나 --deny를 붙여 보내세요. 에이전트 세션은 권한을 승인할 수 없습니다.

Job을 실행하고 끝날 때까지 기다리기

jobs run으로 실행 회차를 시작합니다. runs follow는 진행 상황을 계속 보여 주며 Ctrl+C를 누르면 보기만 멈추고 작업은 취소하지 않습니다. 스크립트에서는 runs wait가 실행 회차가 끝나거나 사용자 확인이 필요할 때까지 기다립니다. 에이전트 오케스트레이션

Job의 질문에 답하기

실행 회차에 결정이 필요하면 셸에서 열린 질문을 나열하고 하나를 읽은 뒤 답하세요.

astera questions list --run RUN_ID --status open --human
astera questions answer --id QUESTION_ID --answer "Use the existing authentication library."

다른 컴퓨터에서 작업하기

명령 앞에 --runtime RUNTIME_ID를 넣으면 페어링한 컴퓨터에서 실행됩니다. Remote Runtime

스크립트에서 쓰기 좋게

대부분의 명령은 기본으로 JSON을 출력합니다. 성공하면 "ok": true와 함께 결과가 data에 담깁니다. 실패하면 "ok": false와 함께 error.code, error.details, error.nextSteps가 옵니다. 읽기 쉬운 출력은 --human, ID만 받으려면 --quiet를 붙이세요. runs follow는 이벤트를 줄마다 JSON 하나로 출력합니다. 종료 코드는 코드마다 뜻이 하나입니다.

Astera 1.5.5의 종료 코드. 출처: CLI 문서(영어).

스크립트에서 실행 회차를 기다린 뒤 끝난 방식에 따라 처리하는 예입니다.

astera runs wait --id "$RUN_ID" --timeout-ms 3600000
case $? in
  0) echo "Run finished" ;;
  8) astera questions list --run "$RUN_ID" --status open --human ;;
  10) astera runs checks --id "$RUN_ID" --human ;;
  *) echo "Inspect the run before retrying" ;;
esac

POSIX 셸용 예시입니다. 작업을 바꾸는 명령이 7로 끝났다면 응답만 유실됐을 수 있으니 다시 시도하기 전에 error.nextSteps를 따르세요. CLI 문서(영어)

명령 설치하기

  1. Astera 설치와 계정 추가

    Astera를 설치하고 계정을 추가해 로그인하세요. 사용할 Claude Code나 Codex CLI도 설치합니다.

  2. astera 명령 설치

    설정 → CLI → 명령줄 도구 (astera)를 열고 astera 명령 설치를 누르세요. Windows에서는 이 폴더를 사용자 PATH 에 추가를 켜 두세요. macOS와 Linux에서는 명령이 ~/.local/bin에 설치되며 필요하면 패널에 나온 PATH 명령을 실행하세요. 설치 후에는 새 터미널을 여세요.

  3. Host 시작과 확인

    host status의 data.features에 이 Host가 할 수 있는 일이 나옵니다. spawn은 워커 실행, worktrees는 워크트리, dispatch는 Job 자동 실행과 검사, rolling은 계정 전환입니다.

astera version
astera host start
astera host status
astera accounts list --human

ACCOUNT_ID에는 계정 목록의 ID를, REPO_PATH에는 프로젝트의 절대 경로를 넣으세요. SESSION_ID, JOB_ID, RUN_ID는 그 대상을 만든 명령 결과의 data.id에서 가져옵니다. 가이드: Headless CLI

요구 사항과 한계

  • 앱은 명령 설치, 계정 추가, 로그인에 한 번 필요합니다. 그 뒤로는 앱을 닫아도 명령이 동작합니다.
  • 작업하는 컴퓨터는 깨어 있어야 합니다. 원격 기능이 꺼져 있고 연결된 클라이언트도 진행 중인 작업도 없으면 Host는 약 1분 뒤 종료됩니다. 앞으로 예약된 Job만으로는 Host가 유지되지 않습니다. host start는 여러 번 실행해도 괜찮습니다.
  • 업데이트 후에는 astera version으로 CLI와 Host 버전을 확인하세요. host start가 9로 끝나면 구버전 Host가 아직 실행 중이라는 뜻입니다. 그 Host의 작업을 마친 뒤 astera host start --replace를 쓰세요. 이 명령은 그 Host의 세션을 끝냅니다.
  • 모델 사용량은 앱에서와 마찬가지로 고른 계정에서 차감됩니다.

자주 묻는 질문

CI에서 호출할 수 있나요?

네. 직접 설정한 로컬 실행 환경이라면 됩니다. Astera가 설치돼 있고 계정에 로그인돼 있으며 Host를 시작할 수 있는 컴퓨터여야 합니다. runs wait를 쓰고 종료 코드에 따라 분기하세요.

Ctrl+C를 누르면 따라가던 실행 회차가 멈추나요?

아닙니다. Ctrl+C는 runs follow의 보기만 멈추고 작업은 계속됩니다. 실행 회차를 멈추려면 astera runs stop --id RUN_ID를 쓰세요.

에이전트도 이 명령을 쓸 수 있나요?

Astera가 시작한 세션에는 이미 명령이 들어 있고 /astera-orchestration이 이 명령으로 Job을 계획합니다. 다만 사람이 내려야 하는 결정도 있습니다. 에이전트 세션은 채팅의 권한 요청을 승인할 수 없습니다.
