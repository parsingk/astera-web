Agents on one computer, managed from another

Remote Runtime splits the work between two computers. The Runtime runs Claude Code, Codex, worktrees, checks, and repairs. The controller is the computer you type on: you drive the work from the Astera app, the astera command, or an MCP client there. A Job does not depend on the controller. If the controller sleeps, shuts down, or loses its network, the Runtime keeps working, and the controller catches up when it reconnects.

When it helps

Leave long Jobs on a computer that stays on

Start a Job from a laptop, close the lid, and check on it later. A disconnected controller shows the Runtime’s last known state, marked as out of date. Losing the connection does not mean the Job failed.

Use the accounts and projects already on a workstation

Work runs with the Runtime’s own accounts and paths. A new remote Job takes a folder on that computer, and sessions start in its registered projects. Astera copies no secret, login, or credential between computers.

Open the same session from two places

Closing a Terminal or Chat tab on the controller leaves the session running on the Runtime. A terminal shown on both computers fits the window of whoever typed last; the other view scales down to show it whole.

Script it, or hand it to an agent

Put --runtime RUNTIME_ID before any astera command, or pass runtimeId to a tool in an MCP client. If the Runtime is unavailable, the command returns an error instead of running on the controller. Headless CLI

Built for a private network

  • The Runtime makes its own TLS key. The controller pins its fingerprint when pairing and refuses a different key from then on.
  • A pairing string has a name, works once, and expires after 10 minutes. Each controller gets its own token, and revoking it closes that controller’s connections at once.
  • Read only allows inspection. Full control also starts and manages Jobs and sessions, which can run any command the Runtime’s user can. Give full control only to a controller you would trust with that user account.
  • A controller works with Jobs, Runs, Tasks, and sessions by their IDs. It has no command to read an arbitrary file, list a folder, or open a shell on the Runtime.
  • Unpairing a controller pauses the scheduled Jobs it created. Only a person on the Runtime can resume them.

Use your LAN, a VPN, or Tailscale, and do not forward the Runtime’s port to the internet. Astera offers no relay and opens no port for you. Remote Runtime is separate from MCP over HTTP, which is plain HTTP and not a secure way to reach another computer.

Set it up

  1. Prepare the Runtime

    Install Astera on both computers. On the Runtime, install and sign in to Claude Code or Codex, and register your project folders. Connect the two computers over your LAN, VPN, or Tailscale.

  2. Turn Remote on

    On the Runtime, open Settings → Remote Runtimes → This computer, choose its LAN or Tailscale address, and click Turn on. The “this computer only” address cannot accept another computer.

  3. Create a pairing string

    Name it and choose Read only or Full control. Copy it straight to the controller: it contains a secret, works once, and expires after 10 minutes.

  4. Pair and start work

    On the controller, paste the string in Settings → Remote Runtimes and click Pair. In Jobs, select the Runtime and its project. In New session, choose where the session runs.

To pair from a terminal on the controller instead:

astera runtimes add --pair -
astera runtimes list
astera --runtime RUNTIME_ID jobs list --human
astera --runtime RUNTIME_ID runs follow --id RUN_ID --human

Paste the pairing string after the first command, then end the input with Ctrl+D, or Ctrl+Z then Enter on Windows. Replace RUNTIME_ID with an ID or name from the list, and RUN_ID with a Run on that Runtime. Remote Runtime in the guide

Requirements, limits, and cost

  • The Runtime runs the Astera desktop app on Windows, macOS, or Linux (the .deb in a desktop session). Setup needs that desktop session; a Linux server with no desktop is not supported yet. Any of the three can be a controller.
  • The Runtime must stay awake. While Remote is on, its Host stays up, even when only a scheduled Job or an unanswered question is waiting. A scheduled time missed while the Host is down is skipped. The Remote Runtime reference has the OS recipes that restart it after a crash or a reboot.
  • Update both computers. An older Runtime cannot report its setup, and an older astera command is treated as an agent.
  • Some things stay on the controller: How It Works records, GitHub writes, and agent browser and app control.
  • There is no Astera server fee and no relay subscription. You pay only for what you choose: the Runtime machine (a VPS or cloud machine, if you use one), a VPN service, and the agent plans or API use of the Runtime’s accounts.

Questions

Does the work stop if my laptop disconnects?

No. A network loss, sleep, shutdown, or a closed app on the controller does not change a Job’s lifetime. The Runtime keeps working, and you read the current progress when you reconnect.

Can the Runtime be a cloud machine?

Yes, if it runs the Astera desktop app: Windows, macOS, or Linux with a desktop session for setup. Reach it over a VPN or Tailscale rather than an open port.

Does Astera copy my logins to the Runtime?

No. Each computer keeps its own accounts and credentials, signed in there. Astera copies no secret, login, or credential between computers in either direction.
