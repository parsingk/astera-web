The Codex CLI, with room around it

Astera starts the codex command installed on your computer and gives each session a pane in one desktop window, next to your Claude Code sessions, files, and worktrees. You keep using Codex the way it works in a terminal; Astera adds accounts, shared tools, checks, and a record of what changed.

Astera is not OpenAI’s Codex app. It is an independent open-source project and is not made by or affiliated with OpenAI.

What you can do with Codex in Astera

Terminal or Chat sessions

Run Codex in its own terminal interface, or as a Chat where questions and approvals arrive as cards. A session keeps the type it was created with. Terminal and Chat in the guide

Several Codex accounts, kept apart

Each Codex account runs with its own CODEX_HOME. When you add an account, Import settings from the default account merges Codex settings into its config.toml and keeps comments and unrelated entries.

Shared MCP servers, skills, and plugins

Choose MCP servers and skills once in Settings → MCP & Skills, and new sessions on every account get them. Provider support still applies: Codex has no slash commands or subagents. Shared Claude Code plugins are also installed into every Codex account; agents are left out, and commands become skills named <plugin>:source-command-<name>. MCP & Skills in the guide

A sandbox that keeps work in its folder

Turn on Run in the sandbox in an agent profile to use Codex’s own sandbox, which limits writes to the work and temporary folders and blocks login files. It needs Codex 0.160.0 or later; on Windows, each Codex account needs a one-time Set up with an administrator prompt. The network stays available. Sandbox in the guide

Codex and Claude Code on the same work

A Job can give some tasks to Codex and others to Claude Code, then ask the other provider’s model to review each result. A cross-vendor review uses that provider’s quota. Agent orchestration with Jobs

Continue after a usage limit

When a Codex session reaches its limit, Astera can wait for the reset and resume it, or continue on another Codex account you have registered and are entitled to use. Every account keeps its own limits. Smart Resume can hand the next session a compact checkpoint.

Get started

  1. Install the Codex CLI

    Install Codex so the codex command is on your PATH. Astera starts that command; it does not include Codex.

  2. Install Astera

    Download the installer for your operating system. Installation steps

  3. Add your Codex account

    In Accounts, use Auto-detect or Add account, and finish Codex’s sign-in when prompted.

  4. Start a session

    Open New session, choose the project folder and the Codex account, pick Terminal or Chat, and click Start. Your first session

Requirements and limits

  • Windows 10 or 11, macOS 12 or later, or Ubuntu 22.04 / Debian 12 or later.
  • The Codex CLI installed and signed in. The sandbox needs Codex 0.160.0 or later.
  • Astera is free and open source (Apache-2.0). Codex usage counts against your own OpenAI plan, where local messages and cloud chats share the plan’s usage allowance. In a Codex CLI session, /status shows your remaining limits. OpenAI: Codex pricing and limits

Questions

Is Astera OpenAI’s Codex app?

No. Astera is an independent open-source workspace that runs the Codex CLI. It is not made by or affiliated with OpenAI.

Can Codex review Claude Code’s work?

Yes. In a Job, a task that asks for a review is normally reviewed by the other provider’s model, so Codex can review work Claude Code did, and the other way round. You need a usable account for the reviewing provider.

Do Codex and Claude Code share an account?

No. Each account in Astera belongs to one provider. Account rolling only moves a session to another account of the same provider.
